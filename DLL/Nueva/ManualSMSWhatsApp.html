2Instalación y registro

Cuatro pasos. Solo el registro pide permisos de administrador.

Elige la carpeta de la DLL

Una carpeta donde los usuarios de tu aplicación puedan escribir, por ejemplo la de tu aplicación o C:\SMSWhatsApp\. Evita Program Files si tu aplicación es de VFP, salvo que tu instalador haga lo que dice el aviso de abajo.

Copia los archivos

La DLL protegida es un solo archivo: smswhatsapp.dll. No necesita los archivos .tlb ni .vbr. Junto a ella, los tres archivos del runtime si no lo instalaste con su instalador.

C:\SMSWhatsApp\ ├── smswhatsapp.dll ← la DLL ├── vfp9r.dll ← runtime (si no está instalado) ├── vfp9renu.dll ├── msvcr71.dll └── smswhatsappr1.dll ← la crea el runtime la primera vez (ver aviso)

Regístrala como administrador

Abre Símbolo del sistema con Ejecutar como administrador. En Windows de 64 bits usa el regsvr32 de 32 bits:

Windows de 64 bits
C:\Windows\SysWOW64\regsvr32.exe "C:\SMSWhatsApp\smswhatsapp.dll"
Windows de 32 bits
regsvr32 "C:\SMSWhatsApp\smswhatsapp.dll"

Debe responder «DllRegisterServer en … se realizó correctamente». Desde un instalador, agrega /s para que no muestre ventanas.

La DLL en Program Files con una aplicación de VFP. La primera vez que una aplicación de VFP crea el objeto, el runtime de VFP 9 deja junto a la DLL una copia de sí mismo llamada smswhatsappr1.dll. En Program Files, un usuario sin permisos de administrador no puede crearla y CreateObject falla con 0x80004005 («Error no especificado»).

Soluciones: instala la DLL en una carpeta donde el usuario pueda escribir, o haz que tu instalador (que corre como administrador) copie vfp9r.dll en la carpeta de la DLL con el nombre smswhatsappr1.dll. Las aplicaciones que no son de VFP (.NET, VBScript) no necesitan esa copia.

Ciclo de vida del objeto

Varios objetos y varios programas

  • Cada objeto tiene su propia sesión de datos y su propio resultado: el error de uno no aparece en otro.
  • Varios programas pueden usar la misma carpeta a la vez: las tablas de salida, la caché y el log no se dañan.
  • Mientras un método trabaja, tu aplicación espera; Windows no la marca como «No responde». Si un Timer o un clic llama a otro método del mismo objeto durante la espera, esa llamada se rechaza con el código 134 sin tocar la que está en curso.

  • Si cargas el .cfg de otra cuenta, vuelve a llamar a ValidateClient() con su token.
  • Si otro programa tiene abierto el .cfg, la DLL espera medio segundo y, si sigue tomado, carga la DEMO con nErrorCode 136.

La versión DEMO

Sin activar, el objeto funciona como DEMO:

  • 20 mensajes por día por objeto (el cupo vuelve a 0 al cambiar el día). Al agotarse: nErrorCode 4.
  • Cada mensaje lleva un pie con datos del equipo que envía (nombre del equipo, usuario de Windows, IP local y pública, MAC, país, ciudad), y el destinatario los ve. La IP pública y la ubicación se consultan a un servicio externo, una vez por objeto.
  • Los métodos que necesitan una licencia activada responden ERROR: [Este método necesita una licencia válida y activada.] con nErrorCode 3.

Si cargas una licencia y envías sin activar (o después de una activación que falló), el mensaje sale por tu cuenta pero como DEMO, con el pie y el cupo de 20. Revisa siempre que la activación dé nStatusCode = 200 antes de enviar.

Cuida el ID y el token como una contraseña: no los dejes escritos en el código fuente ni en un archivo que vean los usuarios. Guárdalos cifrados en tu configuración.

5Cómo leer los resultados

Después de cada método, tres propiedades te dicen qué pasó.

PropiedadQué tieneÚsala para
nStatusCode200 = salió bien; 0 = falló.Decidir.
nErrorCodeEl código real del error: 0 si no hubo error. No depende del idioma.Saber la causa y reaccionar.
cLastErrorEl mensaje para mostrar: OK: [...] o ERROR: [...], en el idioma de cLanguage.Mostrarlo o guardarlo. No para decidir.

Anatomía de cLastError

ERROR: [El archivo C:\MiApp\factura.pdf no existe o su ruta no es válida.]
ERROR: [No se pudo conectar con el servidor.] [Intento 1: …] [URL: https://…/****]
Resultado: OK: o ERROR:
El mensaje, entre el primer [ y su ]
Detalle técnico opcional, en otros corchetes

Para quedarte solo con el mensaje: StrExtract(loWS.cLastError, '[', ']'). Si el mensaje trae un ] (el nombre de un grupo «Ventas [Norte]», por ejemplo), se corta ahí. Tienen formato propio ShowStatus() (un reporte de varias líneas), SendContactsToFile() (agrega una línea File: …) y SendSMSWhatsApp() con varios destinatarios (un bloque por línea).

Los rangos de nErrorCode

0Sin error
1 – 399Detectado por la DLL (tabla)
400 – 599Código HTTP del servidor
12001 – 12999Falla de red de Windows
negativoError de VFP (un archivo tomado, por ejemplo)

El patrón recomendado

Visual FoxPro
loWS.SendSMSWhatsApp(lcNumero, lcTexto)
Do Case
	Case loWS.nStatusCode = 200
		*: Salió (aceptado por el servidor)
	Case InList(loWS.nErrorCode, 6, 11)
		*: El número no es una cuenta de WhatsApp: corrige el dato, no reintentes
	Case loWS.nErrorCode = 3
		*: Falta activar la licencia
	Case Between(loWS.nErrorCode, 12001, 12999) Or loWS.nErrorCode = 204
		*: Problema de red: reintenta más tarde
	Otherwise
		=MessageBox(loWS.cLastError)
EndCase

Ningún error interno llega como excepción. Los métodos nunca disparan un error COM en tu aplicación: devuelven su valor con ERROR: [...], nStatusCode 0 y nErrorCode. La única excepción es CreateObject, que falla si la DLL no está bien instalada (sección 13).

12Buenas prácticas y límites

	

		
TemaQué saber

		
			
«OK» no es «entregado»Un OK de un envío quiere decir que el servidor lo aceptó. La entrega la informa GetAckMessage() (2 = recibido, 3 = leído), y puede decir 0 un rato aunque ya haya llegado. Si necesitas certeza, confírmalo con el destinatario.

			
Mensajes duplicadosUna falla de conexión que no es un tiempo agotado se reintenta hasta dos veces. Si la conexión se cortó después de que el servidor recibió el envío, el mensaje puede llegar dos o tres veces. Si un envío falló por tiempo agotado (12002), revisa el chat antes de reenviar.

			
Doble clicTu aplicación espera mientras la DLL trabaja; un clic hecho durante la espera se atiende al terminar. Un segundo clic en tu botón «Enviar» envía otra vez: desactiva el botón mientras envías.

			
Notas de vozEnvía audios en .ogg (Opus), como las notas de voz de WhatsApp. Un .mp3 puede llegar sin poder escucharse. El texto de un audio va en un mensaje aparte, enseguida.

			
Barras en el textoEl texto se toma como JSON: \n es un salto de línea, \t un tabulador. C:\nuevo llega como «C:», salto de línea y «uevo». Para mostrar una ruta, duplica la barra (C:\\nuevo) o usa /.

			
50 destinatariosEs el máximo por llamada (código 40). Parte la lista.

Preguntas frecuentes

	

		
¿Puedo crear varios objetos a la vez?
Sí. Cada uno tiene su sesión de datos y su resultado. Si son de cuentas distintas y trabajan en la misma carpeta, dale a cada uno sus propias rutas de tablas.

		
¿Tengo que activar cada vez que creo el objeto?
Sí: la activación es del objeto. Por eso conviene crear uno al iniciar tu aplicación y reusarlo.

		
¿Puedo cambiar el idioma de los mensajes?
Sí, con cLanguage: 'ES' (español, por defecto) o 'EN' (inglés). 'FR', 'PT_BR', 'PT_PT' e 'IT' se aceptan y usan el inglés donde no tienen texto propio. Ejemplo en inglés: OK: [593987654301 is an active WhatsApp account.]

		
¿Cómo sé el ID de un mensaje recibido?
En la columna SERIALIZED de MsgChats. Los recibidos empiezan con false_ y los que envió tu cuenta con true_.

		
¿Qué pasa a la medianoche si el objeto sigue abierto?
Nada especial: un objeto puede seguir abierto de un día al otro, y las esperas que cruzan la medianoche terminan cuando deben. El cupo diario vuelve a 0.

		
¿Dónde están los datos de soporte?
En la sección 15. GetInfoDeveloper() también los devuelve, junto con la versión de la DLL.
